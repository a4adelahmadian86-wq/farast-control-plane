# کنترل تغییر و تأیید

## بدون تأیید صریح مالک ممنوع
- ادغام به شاخه اصلی یا انتشار تولید.
- حذف/بازنویسی قابلیت موجود یا داده.
- migration مخرب، حذف جدول/ستون یا تغییر داده انبوه.
- تغییر روش احراز هویت، نقش‌های اصلی، سیاست حریم خصوصی یا دوره نگهداری.
- تغییر gateway، هزینه واقعی، اشتراک و تعهدات مالی.
- تغییر دسترسی‌ها، secrets، repository visibility یا تنظیمات امنیتی.
- پذیرش ریسک امنیتی بحرانی/بالا.
- ایجاد هزینه یا استفاده از سرویس پولی.

## مجاز با کنترل
تحلیل read-only، تهیه گزارش، تست محلی/ایزوله، اصلاح branch اختصاصی، افزودن تست و مستندات غیرمخرب در محدوده وظیفه.

## اصل دو مرحله‌ای
پیشنهاد عامل ≠ تصمیم مصوب. تغییر باید ابتدا پیشنهاد و شواهد داشته باشد؛ سپس تأیید لازم؛ سپس اجرا و راستی‌آزمایی. برای اقداماتی که مالک صریحاً از قبل مجوز محدود داده، محدوده مجوز و تاریخ آن باید ثبت شود.
