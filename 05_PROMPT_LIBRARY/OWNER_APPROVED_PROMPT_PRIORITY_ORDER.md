# ترتیب اولویت اجرایی مورد تأیید مالک FARAST

وضعیت: مورد تأیید مالک در مکالمه مورخ 2026-11-16؛ مرجع انتشار: main پس از ادغام این تغییر.

## قاعده حاکم

این فهرست، ترتیب اولویت برنامه‌ریزی و تخصیص کار بین ۱۷ پرامپت تخصصی است. شماره PR/EXP شناسه پایدار است، نه hard dependency. ترتیب زیر به‌تنهایی اجرای مستقل را متوقف نمی‌کند و هیچ Work Item را تا تکمیل تمام موارد قبل از خود مسدود نمی‌سازد. فقط وابستگی‌های سخت صریح در `01_STRATEGY/DEPENDENCY_GRAPH.json`، قفل‌های منابع، write policy و شواهد معتبر می‌توانند اجرا را مسدود کنند. `soft_inputs` صرفاً زمینه‌اند و هرگز گیت نیستند.

## ترتیب مورد تأیید

1. **PR-01 — Baseline:** خط مبنا و کشف وضعیت واقعی (EXP-01)
2. **PR-02 — Recovery:** بکاپ، دوام داده و بازیابی (EXP-02)
3. **PR-03 — Capability Discovery:** کشف و کاتالوگ قابلیت‌ها (EXP-03)
4. **PR-04 — Traceability:** ردیابی نیازمندی تا قابلیت و آزمون (EXP-04)
5. **PR-05 — User Scenarios:** سناریوها و سفرهای واقعی کاربر (EXP-05)
6. **PR-06 — Evidence Testing:** آزمون و شواهد اجرایی (EXP-06)
7. **PR-07 — Gap Root Cause:** تحلیل شکاف و علت ریشه‌ای (EXP-07)
8. **PR-08 — Commerce:** تجارت، سفارش، پرداخت و تحویل (EXP-08)
9. **PR-09 — AI Services:** خدمات هوشمند و پردازش فایل (EXP-09)
10. **PR-10 — Architecture/Data:** معماری فعلی و داده (EXP-10, EXP-11)
11. **PR-11 — Authorization:** هویت، نقش و مجوز (EXP-12)
12. **PR-12 — Security/Privacy Audit:** امنیت، حریم خصوصی و حکمرانی (EXP-13, EXP-14, EXP-19)
13. **PR-13 — Target Architecture:** معماری هدف و trade-off (EXP-15)
14. **PR-14 — Hosting/Operations:** هاست، عملیات، بکاپ و انتشار (EXP-16, EXP-17, EXP-18)
15. **PR-15 — Prioritization:** اولویت‌بندی و بسته تغییر (EXP-20, EXP-21)
16. **PR-16 — Implementation:** آمادگی پیاده‌سازی و رگرسیون (EXP-22, EXP-23)
17. **PR-17 — Acceptance/Release:** پذیرش، امنیت، انتشار و پایش (EXP-24 تا EXP-27)

## استقلال و ترتیب موازی

- این ترتیب، اولویت است و نه dependency graph.
- هر پرامپت می‌تواند مستقل یا موازی اجرا شود، مشروط به اینکه hard gateهای واقعی خودش پاس شده باشند و resource conflict نداشته باشد.
- اگر یک مأموریت مسدود شد، عامل باید کار مستقل بعدی را در همان دامنه پرامپت پیدا کند؛ نباید صرفاً به‌دلیل شماره پرامپت متوقف شود.
- تغییر priority صریح مالک در Work Item بر اولویت پیش‌فرض این فهرست مقدم است؛ هرگز برای ایجاد ترتیب زمانی، hard gate مصنوعی نساز.
- پذیرش عادی نیازمند بازبین انسانی دوم، self-review یا تأیید نیروی انسانی دیگر نیست؛ گیت‌های ماشینی و شواهد دقیق مرجع‌اند. تأیید صریح خود مالک فقط در مواردی که سیاست، قرارداد یا قانون برای اقدام حساس الزام کرده است همچنان لازم است.
- مخزن محصول `a4adelahmadian86-wq/non` تا زمان مجوز دقیق یک Work Item مستقل، READ_ONLY باقی می‌ماند.
