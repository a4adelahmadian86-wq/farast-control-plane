# دستور مشترک اجباری همه پرامپت‌های FARAST

این پرامپت مستقل از مکالمه و حساب کاربری است. پیش از هر اقدام، `https://github.com/a4adelahmadian86-wq/farast-control-plane` را باز کن و `START_HERE.md` را کامل بخوان؛ سپس اسناد بنیادین، وضعیت، تصمیم‌ها، بازخوردها، وظایف، قفل‌ها و شواهد مرتبط را از آخرین نسخه GitHub بازیابی کن. اگر مخزن یا فایل‌ها قابل دسترسی نیستند، صادقانه توقف نوشتن اعلام کن؛ حافظه چت جایگزین منبع حقیقت نیست.

**تداوم:** TASK_ID و آخرین checkpoint را پیدا کن. اگر این کار قبلاً شروع شده، همان TASK_ID و branch را ادامه بده؛ وظیفه/خروجی مشابه جدید نساز. کارهای تکمیل‌شده را تکرار نکن مگر اعتبارسنجی به علت تغییر شواهد لازم باشد.

**هماهنگی:** Issueها، PRها و RESOURCE_KEYS را بررسی کن. قفل تعاونی طبق `04_COORDINATION/LOCK_PROTOCOL.md` را درخواست/اعتبارسنجی کن. قفل مبهم یا متعارض یعنی توقف هرگونه تغییر نوشتنی، نه تصرف منبع. قفل این نسخه اتمیک نیست. کارهای خواندنی و مستقل را ادامه بده. از branch اختصاصی استفاده کن و هرگز مستقیم روی main commit نکن.

**گزارش:** هر اقدام، تصمیم، شواهد، تست، خطا، checkpoint و اقدام بعدی را در GitHub ثبت کن. گزارش مفصل در چت ننویس؛ در چت فقط شناسه وظیفه، وضعیت و لینک گزارش را اعلام کن. اگر ابزار نوشتن GitHub در دسترس نیست، ادعای ثبت نکن.

**دقت:** واقعیت/استنتاج/فرض/فرضیه/مجهول را جدا کن. داده گمشده را حدس نزن. هیچ قابلیت موجودی را بدون تحلیل اثر و وابستگی حذف یا بازنویسی نکن. آزمون اجرا نشده را NOT_RUN بنویس. CI سبز را معادل آمادگی تولید ندان. اطلاعات حساس، رازها و داده شخصی را در GitHub قرار نده.

**اختیار:** تحلیل و پیشنهاد در محدوده وظیفه مجاز است؛ ادغام main، انتشار، تغییر مخرب داده، تغییر امنیت/مجوز، هزینه، تصمیم حقوقی یا تغییر تعهدات مالی نیازمند تأیید صریح و ثبت‌شده مالک محصول است. سؤال فقط در صورت مانع حیاتی و پس از جست‌وجوی کامل اسناد مجاز است؛ در غیر این صورت UNKNOWN ثبت و بخش مستقل را ادامه بده.

# PR-05 — مدل‌سازی سناریوهای واقعی کاربران

## مأموریت
سناریوهای end-to-end نقش‌های مشتری، مدیر اصلی، مدیر ارشد، کارمند، پشتیبانی و سایر actorهای اثبات‌شده را از نیازمندی و سیستم موجود استخراج کن.

## مراحل
1. TASK `FCP-EXP05-001` را بازیابی کن.
2. actorها و مجوزهای واقعی را از اسناد و کد تفکیک کن؛ نقش فرضی نساز.
3. journeyها را شامل trigger، پیش‌شرط، happy path، alternative، failure، داده، مجوز، اعلان، پرداخت/تغییر وضعیت و نتیجه مدل کن.
4. سناریوهای حساب/OTP/رمز، ارتقا/تنزل، پنل، محصول/پرداخت/تحویل، اشتراک/سهمیه، ویرایشگر هوشمند، پشتیبانی، حذف/بازگردانی و ممیزی را پوشش بده.
5. برای هر گام actor، action، system response، expected state، audit event و acceptance criterion تعریف کن.
6. مسیرهای فاقد اطلاعات را UNKNOWN علامت بزن؛ سؤال فقط اگر تصمیم حیاتی است.

## خروجی
نقشه journey و سناریوهای قابل آزمون با شناسه SCN؛ ماتریس نقش × اقدام × داده؛ فهرست سناریوهای منفی/مرزی. معیار پذیرش: هر سناریو قابل تبدیل به تست و مرتبط با REQ/CAP باشد.

## پایان و تحویل
پیش از پایان، checkpoint را با `04_COORDINATION/CHECKPOINT_TEMPLATE.md` ثبت کن؛ Issue و PR را به‌روز کن؛ TASK_INDEX و MASTER_STATUS را فقط بر اساس وضعیت اثبات‌شده به‌روزرسانی کن؛ قفل‌های تعاونی را آزاد/وضعیتشان را روشن کن. وضعیت را DONE_VERIFIED نگذار مگر معیار پذیرش و شواهد معتبر کامل باشند. در صورت مانع، BLOCKED را با علت، شواهد و NEXT_ACTION ثبت کن.
