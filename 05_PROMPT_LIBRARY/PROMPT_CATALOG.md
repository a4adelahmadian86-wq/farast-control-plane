## اجرای یک متن واحد در چند چت
برای اجرای موازی، فقط MASTER-00 را بدون تغییر در تمام چت‌ها بفرستید و پروتکل [پخش یک پرامپت واحد](../04_COORDINATION/SINGLE_PROMPT_MULTI_CHAT_DISPATCH.md) را رعایت کنید. هر چت خودکار از GitHub یک leaf آزاد را claim می‌کند، آن را اجرا/تحویل می‌دهد و به‌طور پیوسته کار بعدی را پیدا می‌کند؛ تخصیص دستی وظیفه لازم نیست. claim بازنده یا blocker، فقط همان کار را کنار می‌گذارد و discovery/کار مستقل ادامه دارد. تا E2E دو حساب مستقل، این قابلیت تأییدشده نیست.

## قانون استفاده

**درخواست مستقیم جدید مالک:** اگر کاربر در همین مکالمه صریحاً اجرای یک تغییر مشخص روی NON را بخواهد، همان assignment مستقیم بر فیلتر EXP پرامپت تخصصی مقدم است؛ عامل باید درخواست را به GOAL/EXP درست نگاشت کند، Work Item مستقل را ایجاد/بازیابی کند و فقط پس از claim و read-back معتبر تغییر دهد. نبود Issue قبلی یا قفل یک منبع نامرتبط به معنی قفل کل NON نیست. بحث/تحلیل/ابهام همچنان READ_ONLY است و عملیات حساس gate مستقل دارند.
1. برای مأموریت عمومی/هماهنگی که پرامپت تخصصی مشخصی ندارد، `MASTER-00.md` را کپی و اجرا کن.
2. برای مأموریت تخصصی، فقط همان پرامپت PR-01 تا PR-17 را کپی کن؛ همان پرامپت محدوده EXP را مشخص می‌کند، عامل بدون درخواست شماره Issue از مالک صف GitHub را می‌خواند، leaf واجد شرایط را به‌صورت deterministic انتخاب می‌کند و پس از claim/اجرا/تحویل دوباره حلقه را تکرار می‌کند. هر پرامپت دروازه اجباری را در خود دارد و عامل باید `START_HERE.md`، `INTERRUPTION_RECOVERY_PROTOCOL.md` و `MASTER-00.md` را مستقیماً از GitHub بخواند. لازم نیست MASTER-00 را جداگانه به متن پرامپت تخصصی بچسبانی.
3. PRها ترتیب زمانی ندارند؛ وابستگی واقعی و قفل منابع تعیین‌کننده است.
4. برای ادامه کار، همان پرامپت را دوباره بده یا بگو «ادامه بده»؛ TASK_ID و checkpoint مانع شروع مجدد می‌شوند.
5. خروجی نهایی و گزارش‌ها در GitHub ثبت می‌شوند؛ چت فقط خلاصه و لینک می‌دهد.

## استقلال ترتیب و مسیر جهانی

- PR-01 تا PR-17 دسته‌های تخصصی‌اند، نه مراحل زنجیره‌ای؛ اجرای هرکدام با هر ترتیب مجاز است و فقط hard_gates واقعی Work Item ترتیب محلی ایجاد می‌کند.
- تمام پرامپت‌های تخصصی علاوه بر EXP محلی، مسیر جهانی parent_goal_ids شامل G-09 را می‌بینند. conflict در G-09 باید به انتخاب برگ مستقل بعدی منجر شود، نه توقف چت.
- همه پرامپت‌ها قرارداد operation_scope_version=1.0 و requested_operations را برای WRITE_ALLOWED اعمال می‌کنند؛ bundle باید دقیقاً از MASTER-00 و ۱۷ منبع canonical ساخته شود.
- canonical backup/recovery در EXP-02، Issue #66 / WI-EXP02-BACKUP-RECOVERY-001 است؛ Issue #14 سابقه superseded و غیرقابل تکثیر است.

## قاعده ضروری چندچتی برای همه ۱۷ پرامپت

هر مکالمه جدید باید CHAT_ID مستقل و تصادفی بسازد و آن را فقط در همان مکالمه نگه دارد؛ تمام پرامپت‌های اجراشده در یک مکالمه همان شناسه را استفاده می‌کنند. قفل یک CHAT_ID فقط همان مکالمه را محدود می‌کند. منابع جدید NON باید با file/dir/module keys دقیق قفل شوند؛ `repo:non:controlled-implementation` قفل کل مخزن است و کلید پیش‌فرض مأموریت‌های جدید نیست. صف/CAS هماهنگ‌کننده را با قفل منابع اشتباه نگیر؛ برای جزئیات و recovery به MASTER-00 و COORDINATOR_COMMANDS مراجعه کن.
